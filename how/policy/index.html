    Policy network¶

    Summary

    One actor-critic network with 196,384 parameters is evaluated once per pick. It encodes each aircraft slot with the same weights (a scalar branch, a route branch and an action-history branch, fused into a 128-dimensional embedding), lets the slots exchange information through one masked self-attention block, and pools them with the encoded global features into a 256-dimensional state context. The critic reads the context. Three policy heads read the context next to each aircraft embedding and are sampled in order: which aircraft, which clearance for that aircraft, and whether to pick again before simulated time advances. Each stage is masked to what is feasible. The TMB and PMS policies have the same architecture and differ only in their weights.

    Source: single-agent/network/rlm.py (ATCEncoder, FlightPlanConvEncoder, AircraftSelfAttention, ATCAutoregressiveNetwork), single-agent/network/autoregressive_policy.py (ATCAutoregressivePolicy, warm_start_policy), single-agent/jax_ppo/network.py (the same network as JAX functions), single-agent/config/config.py (sizes).

    Encoding one aircraft¶

    Every slot passes through the same three branches, whichever flight it holds. The inputs are described on the Observations page.

    Branch Input Layers Output
    Scalar 17 aircraft scalars Linear 17→128, layer normalisation, ReLU 128
    Route 20 waypoints × 11 features two one-dimensional convolutions along the route (64 channels, kernel 3, padding 1, ReLU after each), masked mean over the real waypoints, Linear 64→64, ReLU 64
    Action history 8 records × 16 GRU with hidden size 64; its final hidden state 64

    The masked mean uses the flight-plan mask, so padded route rows do not contribute. The three outputs are concatenated (128 + 64 + 64 = 256) and fused by Linear 256→128, layer normalisation and ReLU into the aircraft embedding eᵢ.

    The global features are encoded separately by Linear 4→128 and ReLU.

    Masked self-attention¶

    Separation is a relation between pairs of aircraft, and a pooled average cannot represent which two aircraft are converging. One multi-head self-attention block therefore runs over the ten aircraft embeddings before anything is pooled (AircraftSelfAttention):

    • 4 heads; queries, keys and values are bias-free linear projections 128→64, 16 dimensions per head; scaled dot-product attention;
    • empty slots (mask_aircraft = 0) are masked as keys, so no aircraft attends to a slot without a flight;
    • the attended values are projected back by Linear 64→128 and added to the input, followed by layer normalisation: e′ᵢ = LayerNorm(eᵢ + W · attentionᵢ).

    The refined embedding e′ᵢ of each aircraft thus carries information about the other aircraft in the window.

    State context and critic¶

    The refined embeddings are averaged over the occupied slots (128) and concatenated with the encoded global features (128). The result is the state context c (256).

    The critic is a value head on the context alone: Linear 256→64, ReLU, Linear 64→1. It estimates the value of the current observation for PPO.

    The three policy heads¶

    Each policy head receives, for every slot, the refined aircraft embedding next to the state context, [e′ᵢ ‖ c] (128 + 256 = 384), and applies Linear 384→64, ReLU and an output layer with the same weights at every slot.

    Head Output Read as
    Aircraft 1 logit per slot: 10 categorical distribution over the slots
    Clearance 15 logits per slot: 10 × 15 categorical distribution over the clearances of the chosen slot
    Again 15 logits per slot: 10 × 15 Bernoulli distribution at the chosen (slot, clearance)

    The clearance and again heads produce an output for every slot, not only for the chosen one. With ten slots this costs little, and it allows the entropy of the whole decision to be computed exactly (below).

    Sampling an action¶

    The joint policy is factorised as

    π(a, c, g | o) = π_A(a | o) · π_C(c | a, o) · π_G(g | a, c, o)

    where a is the aircraft, c the clearance and g the again flag. The clearance is chosen for the aircraft just selected, and the flag for the aircraft-clearance pair just selected.

    1. Stage 1, select aircraft. The aircraft logits of slots outside the aircraft-selection mask (mask_select) are replaced by −10⁸ before the softmax. This excludes empty slots, flights that are not yet under control, and an aircraft already cleared in the current decision interval.
    2. Stage 2, select clearance. The row of clearance logits of the chosen slot is masked in the same way with that slot's clearance mask (mask_action_per_ac).
    3. Stage 3, request reselection. The again logit at the chosen (slot, clearance) defines a Bernoulli distribution. It is masked, so that the flag is 0, when the reselection mask (mask_again) is 0 or when the chosen clearance is do nothing, which always ends the decision interval.

    The masks are part of the observation. A masked choice has a probability that is zero to floating-point precision, and no gradient flows through it. What the environment does with the flag is described under Reselection.

    The log-probability of the joint action is the sum of the three stages, log π = log π_A + log π_C + log π_G. A stage in which only one outcome is possible contributes zero. Deterministic evaluation takes the most probable aircraft and clearance and sets the flag when its logit is positive.

    Entropy. The entropy bonus of PPO uses the entropy of the whole decision tree, not that of the sampled branch:

    H = H(a) + Σ_a p(a) · [ H(c | a) + Σ_c p(c | a) · H(g | a, c) ]

    It is a function of the observation only, so the same value is obtained when acting and when training.

    Permutation equivariance¶

    The same encoders are applied to every slot, the network has no positional input, self-attention with a key mask commutes with a reordering of the slots, and the pooled context is a mean. Reordering the slots therefore reorders the per-aircraft outputs (aircraft logits, clearance rows, again rows) in the same way and leaves the value unchanged: the decision represented by the state does not depend on which slot a flight occupies.

    Initialisation and warm starts¶

    Linear layers of the encoder and the hidden layers of the heads are initialised orthogonally with gain √2 and zero bias, the GRU with orthogonal weights and zero bias. The output layers of the aircraft and clearance heads use gain 0.01, so the initial policy is close to uniform over the feasible choices; the output layer of the value head uses gain 1.

    Three choices make it possible to extend a trained policy without changing what it computes at the moment of the extension (single-agent/main_jax.py --init-weights, which calls warm_start_policy):

    • New input columns start with zero weights. When the first scalar layer is widened, for example by the four AMAN-sequence columns or the clearance flag, the existing columns are copied and the new ones are set to zero.
    • The residual branch of the self-attention block starts at zero. Its output projection is initialised to zero, so at first the block passes on only the normalised input embedding.
    • The again head starts with a small, uniform probability. Its output weights are zero and its bias is −3 (Config.AGAIN_INIT_LOGIT), so every flag starts at sigmoid(−3) ≈ 4.7%.

    Any other mismatch between a source checkpoint and the network raises an error. These choices are a safeguard for warm starts; a from-scratch run begins from the random initialisation above.

    Parameters¶

    Counted from the published checkpoints (artifacts/single_agent/mxp/final_model.zip and artifacts/single_agent/pms/final_model.zip), which have identical shapes.

    Component Parameters
    Scalar branch (Linear, layer normalisation) 2,560
    Route branch (two convolutions, Linear) 18,688
    Action-history branch (GRU) 15,744
    Fusion (Linear, layer normalisation) 33,152
    Self-attention 33,152
    Global encoder 640
    Aircraft head 24,705
    Clearance head 25,615
    Again head 25,615
    Value head 16,513
    Total 196,384

    Two implementations of the same network¶

    The network exists twice, over one set of parameter names. single-agent/network/ defines it in PyTorch as a Stable-Baselines3 ActorCriticPolicy; evaluation and rollout search load the published checkpoints through this class. single-agent/jax_ppo/network.py expresses the same computation as JAX functions for training. single-agent/tests/test_jax_equivalence.py checks that the two give the same outputs, and a JAX-trained policy is saved as an ordinary Stable-Baselines3 checkpoint (single-agent/jax_ppo/export.py).
